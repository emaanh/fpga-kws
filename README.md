# fpga-kws

Keyword spotting on an FPGA (Digilent Nexys A7-100T). A small depthwise-separable CNN
(DS-CNN-S, 23k params) is trained in PyTorch on Speech Commands v2, quantized to int8 with
power-of-two scales, and runs in hand-written SystemVerilog.

12 classes: silence, unknown, yes, no, up, down, left, right, on, off, stop, go.

| Pipeline | Test accuracy |
|---|---|
| Float frontend + float model | 95.81% |
| Float frontend + int8 model (integer-only reference) | 95.83% |
| Simulated PDM mic -> fixed-point mic path and frontend -> int8 model | ~95.6% |
| RTL (simulation) | bit-exact to the Python models at every stage |

The model is trained with +-10 dB level augmentation so it tolerates the mic level; the
mic path loses ~0.4% vs. the dataset's PCM. The engine uses 16 parallel MACs: 665k cycles
(6.65 ms at 100 MHz) per inference, run every 100 ms in live mode.

Two modes on the board (SW15): features over UART (for testing against the reference), or
live from the on-board PDM microphone:

    mic (2 MHz PDM) -> CIC /25 -> FIR /5 + DC block + gain -> 16 kHz PCM
      -> Hann + 512-pt FFT + 40 mel + log2 every 20 ms -> 64-frame ring
      -> every 100 ms: last 49 frames -> DS-CNN engine -> margin + 3-in-a-row rule -> display

Streaming on held-out audio (kws.eval_stream): ~91% of keywords detected, ~5% wrong word,
~100 false alarms/hour from other speech. Expect to retune on the board.

## Layout

- `python/kws/` data pipeline, log-mel frontend, model, training, QAT, integer reference, export
- `rtl/` inference engine (`kws_engine.sv`), mic path (`pdm_mic`, `cic_decim`, `mic_fir`),
  audio frontend (`audio_frontend.sv`), live controller (`kws_live.sv`), board top level
  (`kws_top.sv`: modes, UART, LEDs, 7-segment display); `rtl/gen/` is generated by `kws.export`
- `constraints/` Nexys A7-100T pins
- `tests/` cocotb testbenches (Verilator), all bit-exact against the Python models: engine,
  mic path, frontend, UART mode end to end, live mode end to end from PDM bits
- `scripts/` bitstream build (openXC7) and Vivado timing check

## Usage

```sh
uv sync
uv run python -m kws.data      # download Speech Commands v2 (~2.3 GB) and build the cache
uv run python -m kws.train     # float training (~8 min on an M-series Mac)
uv run python -m kws.qat       # int8 QAT + integer-only evaluation
uv run python -m kws.export    # ROM hex files, SV package, golden vectors
uv run python -m kws.eval_pipeline   # accuracy through the fixed-point + mic pipeline
uv run python -m kws.eval_stream     # detection rule on a long stream

uv run pytest tests/                                 # RTL vs integer reference (needs verilator)
KWS_N_CLIPS=all uv run pytest tests/test_engine.py   # whole test set (~1 h)

scripts/build_bitstream.sh           # build/bit/kws_top.bit with openXC7 (~45 s)
scripts/build_bitstream.sh program   # build and load over JTAG (openFPGALoader)
uv run python -m kws.host            # run the test set on the board over USB-UART (SW15 off)
uv run python -m kws.record out.wav  # record the board mic (SW15 + SW14 on)

vivado -mode batch -source scripts/vivado_synth.tcl  # optional Vivado timing sign-off
```

The bitstream flow needs sv2v, yosys and openFPGALoader (Homebrew) plus nextpnr-xilinx,
prjxray and an xc7a100t chipdb under `$OPENXC7` (default `~/tools/openxc7`).

The build tries 8 placement seeds in parallel and keeps the fastest; with the live path the
best seeds reach ~104 MHz (estimated) against the 100 MHz target, so the margin is thin until
a Vivado sign-off run.

## Board controls

| Switch | Function |
|---|---|
| SW15 | 0: UART feature mode, 1: live microphone mode |
| SW14 | live mode: stream mic PCM over UART (`kws.record`) |
| SW13 | sample the mic on the falling clock edge instead of the rising edge |
| SW5:4 | detection margin: 00 = 2^18 (default), 01 = 2^17 (more sensitive), 10 = 2^19, 11 = off |
| SW3:0 | mic gain, 6 dB steps (0..12); 6 = +36 dB is the starting point |

LEDs: 11:0 class (UART mode) or mic level meter (live mode), 12 word shown, 13 live mode,
14 engine busy, 15 heartbeat. The 7-segment display shows the word. CPU_RESET resets.

UART protocol (1 Mbaud 8N1): send `'I'` + 1960 int8 features; the board replies `'R'`, the
class index and 12 little-endian int32 logits. In record mode each PCM sample is 3 bytes:
`{1, 00000, x[15:14]}, {0, x[13:7]}, {0, x[6:0]}`.
